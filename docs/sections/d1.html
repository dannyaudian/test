D1

Deliverable 1 — Frontman Flow and Automated Administration

One workspace: data is entered once, the next process is submitted from the same screen, and Administration works from a queue — not from duplicate copies.

What changes

Administration is no longer a manual handoff chain. Frontman submits the next step; the system carries the SPK, SO, and billing numbers; Administration verifies work that enters the queue.

Features

Digital SPK, entered once

Identity, contact, purchase method, transaction structure, unit, STNK name, and initial documents are entered by Frontman as the data owner. The system issues the Customer ID and SPK number. Administration does not retype fields that are already valid.

Example in the mockup Dewi: buyer form + Yaris unit (+Agya) + STNK city. Save first to get SPK/26/CLD/00426. The same data appears in Saved SPK — not a second form.

Upload documents before booking fee

The Document Gate opens the booking fee billing request — not the Sales Order directly. Without the required package, the fee request is not issued. See also D3 and the document flow.

Example in the mockup The fee request button stays closed until KTP/KK/NPWP are available. Sarah without NPWP remains blocked in Raize 00423 — not the discount queue.

Booking fee after SPK is saved

The minimum amount follows the vehicle master (for example Yaris Rp 3.000.000). The request is locked. A verified fee is the non-waivable requirement to create the SO — not an Approval Engine object.

Example in the mockup Frontman desk #booking: Rp 3.000.000 cannot be changed. Customer: Digiroom link or scan QRIS. EDC only on the salesperson's device.

Sales Order after fee is met

The system carries SPK data into the SO, keeps the SPK number on each SO, and extends the same lineage into billing. One SPK can contain multiple units/SOs; each trail still belongs to that transaction.

Example in the mockup After KWT/26/CLD/009301, SO 4500091426 in #so. Buyer, STNK, and PO-area OTR are not retyped.

Submit the next step from one platform

Once requirements are met: settlement, billing, AFI/DO, and delivery can proceed. Failed gates hold the process. Waivable rules can be submitted as exceptions; non-waivable rules must be completed, not overridden.

Example in the mockup Budi submits AFI from the SPK workspace #afi. Breaking AFI/billing sequence only goes through #exc_afi. Name ≠ STNK: #exc_nama — not a fee waiver.

Administration Queue + Audit

Work enters the queue with timestamps (volume and aging/SLA). Every action has an actor, time, and reason. Administration verifies and adds internal data instead of copying Frontman forms.

Example in the mockup List in FAST home and the Needs My Action queue. Not a separate spreadsheet.

Flow in the mockup

Fill SPK→Upload documents→Request booking fee→Fee receipt→Sales Order→AFI / billing / delivery
